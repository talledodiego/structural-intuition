# Localisation (i18n)

Every applet is available in Italian and English.

## Rules

1. **Italian is the source language.** Didactic texts are written in Italian first; English is a translation reviewed by a human before publication.
2. **Language comes from the URL.** `?lang=it` (default) or `?lang=en`. Any other value falls back to Italian.
3. **No user-facing text in code.** All titles, labels, explanations, options, feedback and axis labels live in `apps/<slug>/strings.py`.
4. **Same keys in both languages.** A test (`test_strings.py`) fails if a key is missing in one language.
5. **Use the glossary.** Technical terms follow `docs/glossary.md`. A new term is added to the glossary in the same change that introduces it.

## What is not translated

- Code, identifiers, comments (English).
- Equations, symbols and units (identical in both languages).
- References to standards (EN 1993-1-1 is the same everywhere).
- Numbers: always a dot as decimal separator, in both languages.

## `strings.py` format

```python
STRINGS = {
    "it": {
        "title": "Instabilità euleriana",
        "intro_text": "Comprimi un'asta snella e osserva quando si inflette.",
        "axis_slenderness": "Snellezza λ [-]",
    },
    "en": {
        "title": "Euler buckling",
        "intro_text": "Compress a slender member and watch when it bends sideways.",
        "axis_slenderness": "Slenderness λ [-]",
    },
}
```

- Keys are English `snake_case`, grouped by section prefix: `intro_`, `explore_`, `why_`, `axis_`, `label_`, `result_`.
- Long texts (the *Why?* section) may use Markdown and LaTeX (`$...$`).
- Strings with values use Python format fields: `"Pcr = {value:.0f} kN"`.

## Usage in `app.py`

```python
from shared.i18n import get_lang, translator

lang = get_lang()                 # reads ?lang= from the URL
t = translator(STRINGS, lang)     # t("title") -> str
```
